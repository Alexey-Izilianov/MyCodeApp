**MyCodeApp** — редактор кода на C++20 и Qt 6 / QML с упором на скорость:
файлы до 1 ГБ с редактированием, несколько курсоров, LSP, Git и Mercurial,
темы, сниппеты, плагины и офлайн-ассистент, чья языковая модель лежит в
пакете — код не уходит в интернет.

`#cpp` `#cpp20` `#qt` `#qt6` `#qml` `#code-editor` `#text-editor` `#tree-sitter`
`#lsp` `#libgit2` `#mercurial` `#piece-table` `#llama.cpp` `#offline-ai`
`#local-llm` `#astra-linux` `#windows` `#linux`

## Возможности

**Редактирование**
- Несколько курсоров: Alt+клик, курсоры выше и ниже, выделение следующего
  вхождения, выделение столбцом. Любая правка на всех курсорах отменяется
  одним шагом.
- Умный ввод: парные скобки и кавычки, оборачивание выделения, автоотступы,
  отступ табами или пробелами — как в файле, подсветка парной скобки.
- Сворачивание блоков по скобкам и отступам, миникарта с тремя масштабами.
- Перенос строк по словам (Alt+Z). Разделённый экран: вкладку можно утащить
  вправо (Ctrl+\); открепление вкладки в отдельное окно — из меню на вкладке
  или перетаскиванием за границу окна; в отдельном окне работают языковые
  серверы и ассистент.
- Сниппеты с позициями ввода (Tab / Shift+Tab), зеркалами и переменными —
  в формате VS Code.

**Файлы и проект**
- Кодировки UTF-8, UTF-16 LE/BE, Windows-1251, Latin-1 с автоопределением;
  переводы строк LF / CRLF / CR сохраняются и переключаются в меню «Файл».
  Атомарное сохранение; ошибка записи не теряет вкладку.
- Файлы до 1 ГБ: от 256 МБ — файл отображается в память и
  **редактируется**; сохранение идёт в фоне с индикатором, полный текст
  в память никогда не собирается. Несохранённые правки переживают сбой.
- Папка проекта: дерево с учётом `.gitignore`, сессия (вкладки, курсоры,
  прокрутка), слежение за изменениями на диске, Ctrl+P.

**Подсветка**
- C/C++, Python, QML (с JavaScript), Markdown, CMake — tree-sitter в фоновом
  потоке с инкрементальным пересчётом; JSON — регулярные выражения.
- В Markdown код в ``` подсвечивается грамматикой своего языка
  ([tree-sitter-markdown](https://github.com/tree-sitter-grammars/tree-sitter-markdown), MIT).
- Образец цвета при наведении на `#rrggbb` / `rgb()`; значки файлов по языку.

**Поиск и замена (найденное)**

Файл и проект: обычный текст, «Aa» — регистр, «ab» — целое слово,
«.*» — регэксп с `^`/`$` по строкам; ошибка выражения показывается в строке
поиска без диалога; сканирование регэкспа ограничено по времени (защита от
ReDoS). Поиск по проекту — в фоне, с превью и прогрессом.

**Языковые серверы (LSP)**
- clangd, qmlls, pyright, rust-analyzer: автодополнение с документацией,
  подсказки при наведении, переход к определению, ссылки, переименование,
  форматирование, диагностика с панелью «Проблемы».

**Git и Mercurial** (libgit2 и `hg`, без сети)
- Буквы состояния в дереве, полоски изменений в gutter, просмотр изменений,
  панель: индекс, отмена, коммит, ветки.
- История (Ctrl+K H): граф веток, файлы коммита, их изменения, переключиться
  на коммит, создать ветку, скопировать хэш.
- Сообщение коммита — по кнопке «Предложить» (составляет модель).

**Офлайн-ассистент — модель из пакета**
- `Qwen3-4B-Instruct-2507` (Apache 2.0) лежит рядом с программой и
  запускается встроенным [llama.cpp](https://github.com/ggml-org/llama.cpp):
  никаких Ollama, серверов и интернета. Первый вопрос — с загрузкой модели
  за 5–10 с, дальнейшие ответы сразу; потоковый вывод; ~3 ГБ ОЗУ на время
  работы; без видеокарты.
- Объяснить код, написать документирующий комментарий и вставить его,
  объяснить ошибку компилятора, пересказать большой журнал, предложить
  сообщение коммита; свободные вопросы — в том же разговоре.
  Язык ответа — язык интерфейса.
- Альтернативно — через Ollama или OpenAI-совместимый сервер
  (выбор в «Настройки → Ассистент»).

**Расширяемость**
- Темы в JSON (тёмная и светлая встроены, своя применяется при сохранении),
  настраиваемые горячие клавиши, плагины на C++ (Qt-плагины) с включением
  и выключением без перезапуска.

**Прочее**
- Интерфейс на русском и английском, переключение на лету.
- Интеграция с Проводником Windows: «Открыть с помощью» и «Открыть в MyCodeApp»
  для папок; второй запуск передаёт файлы уже открытому окну.
- Портативный режим и профили настроек.
- Astra Linux 1.7–1.8: сборка на 1.7 (glibc 2.28) с Qt из пакета, `.deb`
  с моделью и программной отрисовкой ([tools/astra](tools/astra)).

## Установка

Готовые сборки — в
[Releases](https://github.com/Alexey-Izilianov/MyCodeApp/releases):

- **Windows**: `MyCodeApp-<версия>-win64-setup.exe` — установщик (Program Files,
  ярлыки в меню и на рабочем столе, удаление через «Программы и компоненты»);
  либо `MyCodeApp-<версия>-win64-portable.zip` — распаковать и запустить
  `appMyCodeApp.exe`. Архив портативный: настройки хранятся в папке `data`
  рядом с программой.
- **Linux**: `mycodeapp_<версия>_amd64.deb` — для Ubuntu 22.04+, Debian 11+ и
  Astra Linux 1.8 (`sudo apt install ./mycodeapp_<версия>_amd64.deb`), ставится
  в `/opt/mycodeapp` с ярлыком в меню и командой `mycodeapp`. Для Astra Linux
  1.7 (glibc 2.28) пакет собирается на самой Astra — `tools/astra/package.sh`.

Сборки в Releases идут без модели (вложения GitHub ограничены 2 ГБ): модель
после установки ставит `tools\fetch-model.ps1` при первом запуске с явного
согласия, либо ассистент работает через внешнюю Ollama/сервер. Полный архив с
моделью собирается локально: `./tools/package.ps1` (см. ниже).

Чтобы открывать файлы из Проводника: «Файл → Добавить в «Открыть с помощью»»
(пишет в реестр текущего пользователя, права администратора не нужны).

## Сборка из исходников

Требования: Qt 6.11 (на Windows — MinGW 64-bit), CMake 3.20+, Ninja, интернет
при первой конфигурации (FetchContent скачивает spdlog, tree-sitter, libgit2
и llama.cpp).

```bash
cmake -G Ninja -S . -B build/Release -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=C:/Qt/6.12.0/mingw_64
cmake --build build/Release
powershell -File tools/fetch-model.ps1 -To build/Release  # модель ассистента, 2,3 ГБ
build/Release/appMyCodeApp.exe [--profile имя] [--software] [файл|папка]...
```

`--software` — программная отрисовка без видеокарты (на Linux включается сама,
если OpenGL недоступен).

Полный пакет с моделью: `./tools/package.ps1 -QtBin C:/Qt/6.12.0/mingw_64/bin`
→ `dist/MyCodeApp-<версия>-win64-portable.zip` (2,5 ГБ). Для сборки без модели —
флаг `-SkipModel`.

Установщик Windows (Inno Setup 6): из той же папки, что делает `package.ps1`:
```powershell
& "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" `
  /DMyAppVersion=1.0.4 /DStageDir="$PWD\dist\MyCodeApp-1.0.4-win64" /DOutputDir="$PWD\dist" `
  tools\installer.iss
```
→ `dist/MyCodeApp-<версия>-win64-setup.exe`. Папка `data` в установщик не
попадает: в Program Files она недоступна для записи, поэтому настройки идут в
профиль пользователя.

Astra Linux: скрипты в [tools/astra](tools/astra) — Qt 6.11 из исходников
(`build-deps.sh`, `build-qt.sh`, один раз), затем `build.sh` (сборка и тесты)
и `package.sh` (пакет `mycodeapp_<версия>_amd64.deb` с моделью в
`/opt/mycodeapp`). Для замкнутой программной среды — `SIGN_KEY=<id доверенного
ключа ГОСТ> package.sh`: скрипт добавляет встроенные подписи `bsign` ко всем
ELF. [Документация Astra о ключах ЗПС](https://docs.astralinux.ru/latest/szi/szi/cse/)

После правки строк интерфейса — обновить перевод:
`cmake --build build/Release --target update_translations`, затем перевести
новые строки в `i18n/mycodeapp_en.ts` (Qt Linguist).

## Настройка

Все данные — в папке данных: `%LOCALAPPDATA%/appMyCodeApp`, в портативном
режиме — `data` рядом с exe, для профиля (`--profile имя`) — подпапка
`profiles/имя`. Папку открывает «Справка → Открыть папку данных».

| Что | Где | Как |
|---|---|---|
| Тема | `themes/*.json` | «Вид → Тема → Создать свою тему…» |
| Горячие клавиши | `keybindings.json` | «Файл → Настройки → Горячие клавиши» |
| Сниппеты | `snippets/<язык>.json`, `snippets/global.json` | «Код → Свои сниппеты…», формат VS Code |
| Языковые серверы | `lsp.json` | описание сервера заменяет встроенное (`assets/lsp.json`) |
| Плагины | `plugins/*.dll` и `<exe>/plugins` | «Плагины → Управление плагинами…» |
| Ассистент | `settings.json` | «Настройки → Ассистент»: источник модели (встроенная, Ollama, сервер), размер контекста, проверка |
| Модель ассистента | `models/*.gguf` рядом с программой | переменная `MCA_MODEL` — явный путь |

**Плагин** — Qt-плагин, собранный тем же компилятором и Qt. API —
[include/mycodeapp/plugin.h](include/mycodeapp/plugin.h): команды в меню
и в горячих клавишах, доступ к тексту и выделению. Пример —
[plugins/texttools](plugins/texttools/texttools.cpp).

## Тесты и CI

Qt Test — 15 наборов (piece table, кодировки, документ и история, восстановление, поиск, подсветка, Git/hg, сниппеты, ассистент, редактор через реальные события: клавиатуры и мыши). Запуск локально:
```bash
ctest --test-dir build/Release
```

Замеры производительности — `bench_perf.exe`; генерации модели —
`bench_localmodel.exe` (не автотесты, модель в пакете).

GitHub Actions ([ci.yml](.github/workflows/ci.yml)): сборка и тесты 15/15 на
Windows (MinGW), Linux (GCC) и macOS (Clang). Тесты с окнами идут на
offscreen-платформе с программной отрисовкой — на раннерах нет интерактивного
рабочего стола. Linux с ASan+UBSan и TSan — отдельно; TSan информационный (Qt
не размечен под TSan, его COW-контейнеры дают заведомые срабатывания, они
подавлены в `tools/tsan.supp`). По тегу `v*` в Releases публикуются ZIP,
установщик `.exe` и `.deb` (без модели: ограничение вложений GitHub 2 ГБ).
Если тест упал, разбор пишется в step summary прогона.

`.deb` для CI собирает `tools/package-deb.sh` на Ubuntu 22.04 (glibc 2.35) —
это же собирает пакет локально на любом Debian/Ubuntu:
```bash
./tools/package-deb.sh            # BUILD=build, OUT=dist
```

## Архитектура

```
src/core/       PieceTable + MappedText (mmap), TextBuffer, Document (история),
                потоковое сохранение, свёртка, сниппеты
src/gui/        EditorView (Qt Scene Graph), миникарта
src/services/   вкладки и профили окон, проект, поиск (сегменты и режимы) ,
                подсветка, восстановление, темы, плагины, настройки, локализация
src/lsp/        клиент JSON-RPC и менеджер языковых серверов
src/git/        Git (libgit2) и Mercurial за общим интерфейсом, граф истории
src/assistant/  офлайн-ассистент: встроенная llama.cpp (localmodel), промпты,
                поток ответов, разговор; сервера — по выбору
qml/            интерфейс (вкладки, боковая панель, отдельные окна)
include/        API плагинов
tools/astra/    сборка и пакет для Astra Linux
tools/          упаковка: package.ps1 (ZIP), installer.iss (.exe), package-deb.sh (.deb)
```

- **Текст** — собственная piece table: правка не копирует существующий кусок;
  строковый индекс обновляется инкрементально. От 256 МБ исходник — файл в
  отображении памяти: правки пишутся поверх (piece table), сохранение —
  потоковое, атомарной заменой файла.
- **Фоновые задачи** (поиск, tree-sitter, git) работают с неизменяемыми
  снимками piece table — копия стоит O(1), блокировки не нужны.
- **Правки** идут только через `Document::replace()` — всё попадает в историю
  отмены и в журнал восстановления.
- **Рендер** — `QQuickItem` с нодами Scene Graph: глифы в GPU-атласе, при
  прокрутке меняется только матрица.
- **Модель ассистента** — llama.cpp в рабочем потоке приложения: последняя
  задача отменяет предыдущую, «Стоп» прерывает генерацию, модель остаётся
  в памяти до выхода.
